## Pengenalan proyek

Task Management App adalah ruang kerja full-stack untuk tim kecil yang ingin mengikuti pekerjaan dari ide awal hingga tugas selesai tanpa kehilangan konteks di sekitarnya. Sebuah proyek menampung tim, anggota, dan papan tugas. Setiap tugas memiliki penerima, prioritas, tenggat, progres, status, tag, dan utas komentar. Perubahan muncul sebagai notifikasi dalam aplikasi dan sebagai pembaruan langsung di papan pengguna lain yang sedang masuk.

Skenario yang dituju sengaja sederhana: seorang manager membuat proyek, menambahkan rekan tim, memecah pekerjaan menjadi tugas, lalu memantau papan bergerak dari To Do ke In Progress dan Completed. Seorang anggota membuka proyek yang sama di perangkat lain, mengambil tugas, meninggalkan komentar, dan melihat notifikasi tanpa memuat ulang halaman. Tidak ada kebutuhan akan pipeline deployment atau sistem pembayaran di sini; bagian yang menarik adalah kesepakatan antara API, database, dan lapisan real-time tentang apa yang boleh dilihat dan diubah oleh setiap pengguna.

Kesepakatan itulah yang membuat implementasinya layak didokumentasikan. Repositori awalnya berupa prototipe yang sebagian rusak: ada impor kode server di klien, plugin Vue yang tidak didaftarkan, SQL yang tidak aman, dan middleware kosong. Prototipe ini diperbaiki di tempat dengan tetap mempertahankan struktur folder `client/`, `server/`, dan `database/`, lalu berkembang menjadi sistem dengan peran yang jelas, migrasi yang dapat diulang, lapisan socket terautentikasi, dan alur container dengan startup yang teratur.

## Arsitektur dan alur data

Browser menjalankan single-page application Vue 3. Aplikasi membaca dan menulis melalui REST API di bawah `/api`; koneksi Socket.IO terpisah membawa event langsung kembali ke browser. Backend adalah satu-satunya komponen yang berbicara dengan PostgreSQL, dan Nginx adalah satu-satunya pintu masuk publik dalam tumpukan container.

```text
                     Runtime Docker Compose
  +----------------------------------------------------------------------+
  |  frontend (Nginx :8080)       backend (Node/Express :5000)           |
  |    /api/* --------proxy----->  routes -> middleware -> controllers    |
  |    /socket.io/ -proxy----->   server Socket.IO + registry room        |
  |                                     | SQL berparameter               |
  |                                     v                                |
  |                              postgres (PostgreSQL 15)                |
  +----------------------------------------------------------------------+
          ^                                      ^
          | respons REST + event real-time       | jaringan internal saja
          |                                      |
   +----------------------+              (tidak diakses langsung browser)
   | Browser pengguna     |
   | Vue 3 SPA + Pinia    |
   +----------------------+
```

Saat startup, Compose menunggu PostgreSQL sehat, lalu health check backend lolos, baru menjalankan frontend. Container backend menerapkan migrasi sebelum API dimulai. Nginx melayani SPA hasil build, melakukan fallback ke `index.html` untuk route sisi klien, dan mem-proxy `/api/` serta `/socket.io/` dengan header upgrade WebSocket ke layanan backend. Tidak ada cache, antrean, atau layanan eksternal lain dalam tumpukan ini.

## Catatan implementasi

### Migrasi dan setup yang dapat diulang

Enam file SQL bernomor membangun skema secara berurutan: pengguna, tugas dan tag, komentar, notifikasi, lalu skema lanjutan yang menambahkan tim, proyek, dan tiga enum peran. File seed terakhir memasukkan tiga akun demo, sebuah tim, sebuah proyek, keanggotaan, tiga tugas, tag, komentar, dan notifikasi. Runner mencatat file yang sudah diterapkan di `schema_migrations` dan membungkus setiap file dalam transaksi. Pembuatan tabel memakai `IF NOT EXISTS`, penambahan kolom memakai `ADD COLUMN IF NOT EXISTS`, dan seed memakai `ON CONFLICT DO NOTHING`, sehingga container baru dan container yang dimulai ulang menuju keadaan yang sama.

### Validasi, otorisasi, dan isolasi

Aturan express-validator mencakup autentikasi, tugas, proyek, tim, anggota, komentar, dan ID; input yang tidak valid menghasilkan respons 400 terstruktur. Semua nilai dinamis dalam SQL memakai parameter. Tiga lapisan otorisasi diselesaikan sebelum controller berjalan: peran global (`admin`, `manager`, `member`), peran proyek atau tim (`owner`, `manager`, `member`), dan status sebagai penerima tugas. Query daftar tugas hanya menerima admin, tugas tanpa proyek yang dibuat oleh pemanggil, dan tugas dalam proyek tempat pemanggil memiliki baris keanggotaan. Isolasi resource diuji dengan akun luar yang mendapat 403 untuk operasi baca dan tulis. Filter dan pencarian tugas tersedia; pagination belum diimplementasikan.

### Persistensi Kanban

Tiga kolom memetakan nilai enum `todo`, `in-progress`, dan `completed`. Kartu dapat dipindahkan dengan drag-and-drop bawaan HTML5 dan tetap dapat diakses lewat keyboard. Pemindahan memperbarui store Pinia lebih dulu, mengirim status dan posisi baru ke `PATCH /api/tasks/:id/status`, lalu mengembalikan status lama jika permintaan gagal. Penyelesaian tugas juga menetapkan progres ke 100. Validasi hanya memeriksa bahwa status termasuk enum, sehingga status valid apa pun saat ini dapat diubah dari status lain mana pun.

### Batas real-time

Handshake socket memverifikasi JWT yang sama dengan REST dan memuat pengguna dari database. Setiap koneksi bergabung ke `user:<id>` dan ke room proyek tempat pengguna memiliki keanggotaan; admin bergabung ke semua room proyek. Perubahan keanggotaan memanggil helper sinkronisasi yang menggabungkan atau mengeluarkan socket yang bersangkutan. Event tugas, komentar, dan progres dikirim ke room proyek, sementara notifikasi ditujukan ke room `user:<id>`. Listener untuk event utama berada di `App.vue` agar bertahan setelah reconnect, dan interceptor Axios memutus socket serta menghapus sesi saat menerima 401.

### Alur container

Tiga layanan memakai port host yang dapat diatur lewat environment variabel. Image backend memasang dependency produksi saja, berjalan sebagai pengguna non-root, dan dimulai dengan `npm run migrate && npm start`. Frontend dibangun dalam dua tahap lalu hasil Vite disalin ke Nginx. Health check mengatur urutan startup, dan `.dockerignore` di root menjaga dependency terpasang tetap keluar dari kedua konteks build.

## Verifikasi dan QA

Dokumentasi QA mencatat hasil berikut untuk putaran penerimaan akhir:

- Backend: 16 pengujian, 0 kegagalan, memakai test runner bawaan Node.
- Frontend: build produksi berhasil dengan 140 module yang diproses.
- Container: `postgres`, `backend`, dan `frontend` semuanya sehat; konfigurasi Compose valid.
- API dan real-time: perilaku REST, otorisasi, dan isolasi resource lolos; pengujian dua akun mengonfirmasi pembuatan tugas, pembaruan tugas, komentar, dan pengiriman notifikasi tanpa memuat ulang.
- Browser dan responsif: alur CRUD dan notifikasi lolos pada 1440 × 900, 768 × 1024, dan 390 × 844, tanpa overflow yang dilaporkan.
- Pemeriksaan sumber: `git diff --check` terbatas pada sumber bersih; sebelas file tangkapan layar valid diverifikasi terhadap aplikasi yang berjalan.

Ini adalah hasil terdokumentasi untuk tumpukan evaluasi lokal, bukan bukti bahwa semua skenario produksi sudah diuji. Port host 5000 dan 8080 sedang terpakai di mesin QA, sehingga verifikasi memakai 5001 dan 8081. Laporan rinci ditulis pada commit `974d4b7`; head lokal saat ini menambahkan commit kebersihan dependency. Tidak ada demo daring yang ditautkan, dan tangkapan layar memakai data demo dari seed data.

## Tantangan dan keputusan rekayasa

- **Perbaikan di tempat.** Audit menemukan klien yang mengimpor kode database khusus server, router dan Pinia yang tidak didaftarkan, middleware validasi kosong, skrip pengujian yang selalu gagal, SQL interpolasi, nama event socket yang tidak cocok, dan kunci Compose yang tidak valid. Keputusannya adalah memperbaiki masing-masing di dalam struktur folder yang ada, bukan mengganti framework atau memindahkan direktori utama.
- **User runtime Nginx.** Deklarasi `USER nginx` membuat Nginx gagal dengan error izin saat mencoba membuat `/var/cache/nginx/client_temp`. Image kini membiarkan entrypoint resmi Nginx menjalankan proses master sebagai root sementara worker tetap tanpa hak istimewa.
- **Otorisasi real-time.** Socket tidak dipercaya hanya karena berhasil terhubung. Room berasal dari query keanggotaan, diperbarui saat keanggotaan berubah, dan secara eksplisit memasukkan admin; event kemudian ditujukan ke room tersebut, bukan disiarkan ke semua koneksi.
- **Konflik port saat QA.** Port host yang dikonfigurasi sudah terpakai. Variabel environment `BACKEND_PORT` dan `FRONTEND_PORT` memungkinkan file Compose yang sama diverifikasi di 5001 dan 8081 tanpa mengubah konfigurasi yang tersimpan.
- **Panel notifikasi mobile.** Panel awalnya melekat pada tombol lonceng dan keluar dari layar pada lebar ponsel. Kini panel dipusatkan di bawah header pada layar kecil dan tetap melekat pada tombol mulai dari breakpoint `md`.
- **Aseri browser yang andal.** Salah satu asersi QA awal memeriksa notifikasi memakai akun admin, yang tidak memiliki notifikasi dari seed data. Beralih ke akun demo membuat pemeriksaan menjadi bermakna, dan asersi DOM ditambahkan untuk kondisi seperti `Current members` dan `Initial review completed`.

## Ruang lingkup dan keterbatasan

Berikut ini memang belum diimplementasikan: pengarsipan proyek, endpoint update dan hapus tim, notifikasi tandai belum dibaca, transisi status yang dibatasi, pembatasan penerima tugas pada anggota proyek atau tim, pengubahan judul dan deskripsi tugas di antarmuka, serta pagination. Registrasi, indikator mengetik, dan event progres proyek lewat socket sudah ada tetapi belum sepenuhnya diverifikasi end to end dalam matriks browser akhir.

Tidak ada skrip lint atau typecheck, pipeline CI/CD, monitoring produksi, strategi backup, atau pengerasan deployment selain pengaturan container yang didokumentasikan. JWT tidak memiliki rotasi refresh atau daftar pencabutan, tidak ada rate limiting maupun penguncian akun, dan port 5432 PostgreSQL masih diekspos untuk pengembangan lokal. Kata sandi akun demo hanya untuk evaluasi lokal. Semua ini merupakan kandidat pekerjaan berikutnya, bukan fitur yang sudah selesai; deployment produksi memerlukan tinjauan keamanan dan operasional tersendiri.

## Catatan penutup

Proyek ini menunjukkan aplikasi full-stack yang disusun dari titik awal yang tidak sempurna menjadi sesuatu yang koheren: model relasional dengan peran yang tegas, API yang memegang keputusan akses, lapisan real-time yang mencerminkan keputusan tersebut lewat room, serta tumpukan container yang dimulai secara teratur. Pelajaran paling berguna adalah otorisasi real-time tidak bisa menjadi rencana belakangan — ia harus memakai aturan keanggotaan yang sama dengan API, termasuk ketika keanggotaan berubah.

Keadaan saat ini adalah aplikasi lokal yang selesai dan terdokumentasi QA dengan data demo dari seed data serta sebuah repositori, bukan layanan produksi yang dihosting atau dikeraskan. Proyek ini disajikan di sini sebagai studi kasus teknis tentang implementasi, verifikasi, dan keputusan rekayasa di baliknya.
