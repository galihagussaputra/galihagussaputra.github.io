## Buying flow

The storefront reads the catalog from the API and keeps filters in the URL. A guest cart lives in Redux; after login it is synced to the server cart. Checkout sends only product IDs and quantities. The API reloads prices, calculates shipping and tax, creates a pending order, reserves stock atomically, and redirects the browser to Stripe-hosted checkout. A signed webhook finalizes the order, while cancellation and expiry release the reservation once and restore the cart.

## Server-owned state

JWT authentication and an admin role guard the sensitive endpoints. Product mutations, inventory adjustments, order status changes, and analytics are restricted to admins. Reservation uses conditional updates on available stock inside a MongoDB transaction, and every adjustment is recorded as an append-only stock movement. Webhook event IDs are stored with a processing state so duplicate deliveries cannot mutate an order twice.

## Operations and limitations

Docker Compose runs the frontend, API, and a single-node MongoDB replica set with healthchecks and a persistent volume. The repository includes Jest integration tests, Vitest component tests, seed data, architecture and API documentation, and desktop and mobile screenshots. Checkout requires Stripe test keys and webhook forwarding, so no hosted demo is linked; the screenshots use synthetic seed data.
